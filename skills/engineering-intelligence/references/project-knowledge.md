# Знания о проекте между сеансами

В начале содержательной задачи определи корень проекта по рабочей копии и действующим правилам. Проверь согласованные решения в проектной документации и в локальных заметках именно об этом корне. Перепроверь важные факты по текущему коду, требованиям или экрану. Старая запись указывает, где искать, и сама по себе не разрешает новую правку.

## Где хранить

По умолчанию используй личный локальный журнал **вне репозитория**. Одинаковые названия проектов в разных папках получают разные журналы. Перемещение проекта меняет его идентификатор. Если владелец явно назначил другой документ для записи, используй его в пределах разрешений. Запись в проектные документы, общие сервисы или глобальные правила требует отдельного явного указания.

Если пользователь запретил любые записи, в том числе формулировкой «пока ничего не меняй», либо среда разрешает только чтение, дай готовую краткую запись в чате и укажи, что на диск она не сохранена. При сбое сохранения поступи так же и назови причину. Не переноси содержимое в другой проект или подключённый сервис как обход ограничения.

## Что сохранять

По завершении этапа ведущий объединяет подтверждённые результаты. Запись нужна, когда появилось новое знание, решение или изменился статус проблемы. Включай только относящиеся к делу пункты.

| Что | Что понадобится в следующем сеансе |
| --- | --- |
| Факт о проекте | Поведение, путь и символ или наблюдение. По возможности укажи ревизию или дату проверки. |
| Проблема или открытый вопрос | Где проявляется, на кого влияет, подтверждено ли, что ещё неизвестно. |
| Решение | Что согласовано, кем или в каком запросе, почему и в каких пределах. Предложение до ответа владельца пометь как предложенное. |
| План исправления | Минимальный следующий шаг, критерий готовности и статус. Укажи владельца, если он известен. |

Сохраняй итог без секретов, персональных данных, сырых логов, снимков и копий частного кода. Ссылайся на безопасный источник. Если факт устарел или проблему исправили, добавь запись с полным идентификатором прежнего решения, темой и новой проверкой. При восстановлении темы проверь обновления по ID исходной записи, затем повторяй поиск по ID каждого найденного обновления до последнего статуса. Сверяй действующее правило с решением владельца, а реализованное поведение — с текущим кодом. Различай дату сохранения и дату подтверждения факта.

## Как записать и прочитать

Определи путь к [помощнику](../scripts/project_notes.py) относительно папки **этого навыка**. Передай один и тот же канонический корень проекта при чтении и записи. Например, если `skill_dir` указывает на установленный навык, а `project_root` — на нужный проект, чтение выполняется так.

```sh
python3 "$skill_dir/scripts/project_notes.py" show "$project_root"
```

Для поиска по прошлым решениям добавь `--find 'тема'`. В выводе есть идентификатор каждой записи. Поиск `--find 'полный идентификатор'` находит её и записи, которые на неё ссылаются. Команда `add` принимает один составленный тобой Markdown-фрагмент через стандартный ввод. Здесь `verified_note` содержит готовый безопасный текст. При успехе проверь возвращённый путь и укажи его пользователю. Совпадающая запись учитывается один раз.

```sh
printf '%s\n' "$verified_note" | python3 "$skill_dir/scripts/project_notes.py" add "$project_root"
```

Обычный путь — `${XDG_STATE_HOME:-$HOME/.local/state}/engineering-intelligence/projects/<id>/`, где `<id>` получен из канонического пути корня. Параметр `--store DIR` позволяет выбрать другую разрешённую базу вне проекта, например для изолированной проверки. Помощник работает на Python 3 со стандартной библиотекой. Если его невозможно запустить, сообщи об этом и оставь запись в чате.
