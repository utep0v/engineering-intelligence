# Аудит существующего проекта

Укажи охваченный компонент или каталог. Для большой системы начни с главного пользовательского сценария и расширяй выборку по его связям. Для локального вопроса достаточно затронутого пути.

1. Найди применимые `AGENTS.md`, README, манифесты, lock-файлы, верхний уровень исходников и конфигурацию сборки. Сначала просматривай имена файлов. Содержимое открывай выборочно. Обходи каталоги зависимостей и сгенерированные файлы, если они не составляют сам предмет аудита.
2. Проверь реальную точку входа. Сопоставь объявление запуска, маршрута, команды или публичного экспорта с кодом регистрации и обработчиком. Проследи хотя бы один сквозной путь до наблюдаемого результата. Ищи владельца данных, место чтения и записи, внешнюю границу и поведение при сбое там, где они есть.
3. Проверь направления зависимостей между модулями по вызовам и импортам. Для хранения найди модель, схему или миграцию. Для интеграции свяжи её объявление с вызывающим кодом. Одно имя пакета в манифесте подтверждает только декларацию.
4. Разбери тесты, доступные в выборке, и проследи, какой контракт проверяют их утверждения. Для доставки свяжи объявленную команду сборки или запуска с CI, контейнером либо инструкцией релиза, если они представлены. Наличие конфигурации описывает предусмотренный процесс. Состояние работающей среды требует отдельных данных.

Держи аудит только для чтения. Используй просмотр, поиск по именам и точечное чтение безопасных исходников. Пропускай файлы с секретами и сырые журналы с пользовательскими данными. При смешанной конфигурации запроси при необходимости обезличенную схему. Прогоны, которые создают кэш, артефакты, обращаются к сервисам или меняют данные, оставь для отдельной проверки в изолированной среде.

## Как показать карту AS-IS

- Начни с одного прослеженного пути. Для каждой существенной связи дай относительный путь от корня проекта, при возможности строку или символ, и поясни, что именно там видно.
- Сгруппируй остальные наблюдения по точкам входа, модулям и зависимостям, данным, интеграциям, тестам и поставке. Укажи границу выборки. В небольшом проекте хватит нескольких строк.
- Пометь **факт** с источником, **предположение** с основанием и способом проверки, **неизвестно** с областью поиска. Когда документация расходится с кодом, приведи оба места. Отсутствие файла в дистрибутиве оставляет открытым вопрос о полном репозитории.
- Выдели риски, которые меняют решение пользователя. Свяжи каждый с конкретным местом, последствием и минимальной проверкой. Отдели вывод о текущем устройстве от предлагаемого изменения.
